# Tunneling Hub Server

A tunneling hub using Chisel and Caddy, with a Go API for dynamic name/route management.

## Architecture

Three services run concurrently via `scripts/start.sh`:

1. **Go API Server** (port 3000) - Handles name registration and route management
2. **Chisel Server** (port 8080) - Accepts WebSocket reverse tunnels from clients
3. **Caddy Reverse Proxy** (port 5000) - Public-facing proxy that routes `/{name}/*` to tunnel ports

## Project Structure

```
cmd/api/main.go       - Go API server (name registry + Caddy config management)
scripts/install.sh    - Downloads chisel and caddy binaries to bin/
scripts/start.sh      - Starts all three services
bin/                  - Binary directory (chisel, caddy, api) - gitignored
Caddyfile             - Dynamically generated by the API server
```

## API Endpoints (via Caddy on port 5000)

- `GET /check-name?name=alice` - Check if a name is available
- `POST /claim-name` with `{"name": "alice"}` - Claim a name, get allocated port
- `GET /status` - List all active routes

## How It Works

1. A client calls `POST /claim-name` with a desired name
2. The API allocates a free port (starting at 10042), updates the Caddyfile, and reloads Caddy
3. The client connects chisel to port 8080 and opens a reverse tunnel to the allocated port
4. Public traffic hitting `/{name}/*` is reverse-proxied through Caddy to that tunnel port

## Dependencies

- Go 1.25 (runtime)
- Chisel v1.10.1 (downloaded binary)
- Caddy v2.9.1 (downloaded binary)

## Chisel Client Connection

```bash
chisel client --auth user:secret-token <server-url>:8080 R:<allocated-port>:<local-addr>
```
