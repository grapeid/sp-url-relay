# Replit Deployment — Changes & Setup Notes

This document describes the changes made to adapt `sp-witness-watcher` for hosting on Replit, relative to the original codebase.

---

## 1. Port

The default port was changed from `8092` to `8080` for the Replit development environment. This is handled via the `PORT` environment variable — no code change was required. On a standalone Linux server the original port can be restored by setting `PORT=8092` (or any value you prefer).

**In the workflow run command:**
```
PORT=8080 go run ./cmd/server
```

---

## 2. Dual Database Backend (SQLite ↔ PostgreSQL)

The original codebase used SQLite exclusively. PostgreSQL support was added alongside it — both backends are fully maintained and the switch is a single constant.

### New files

| File | Purpose |
|------|---------|
| `internal/store/interface.go` | Defines the `Store` interface, the `UsePostgres` switch, and the `Open()` router function |
| `internal/store/postgres.go` | Full PostgreSQL implementation of `Store` |

### Modified files (minimal changes)

| File | Change |
|------|--------|
| `internal/store/store.go` | `Open()` renamed to `openSQLite()` — everything else untouched |
| `internal/api/server.go` | `Server.Store` field type changed from `*store.ServiceStore` to `store.Store` interface |
| `cmd/server/main.go` | Backup goroutine wrapped in `if !store.UsePostgres` |

### Switching backends

Edit **one line** in `internal/store/interface.go`:

```go
// Standalone Linux server — uses SQLite in ./data/
const UsePostgres = false

// Replit — uses PostgreSQL via DATABASE_URL (injected automatically)
const UsePostgres = true
```

When `UsePostgres = true` the service reads `DATABASE_URL` from the environment. On Replit this variable is injected automatically when the PostgreSQL integration is active — no additional configuration needed.

### SQL differences between backends

| Feature | SQLite | PostgreSQL |
|---------|--------|------------|
| Placeholders | `?` | `$1`, `$2`, … |
| Auto-increment PK | `INTEGER PRIMARY KEY AUTOINCREMENT` | `BIGSERIAL PRIMARY KEY` |
| Pragmas | `PRAGMA journal_mode=WAL` etc. | Not applicable |
| Upsert | `ON CONFLICT … DO UPDATE` | Same syntax |

## 3. SQLite Hourly Backup

A background goroutine was added to `cmd/server/main.go` that runs when `UsePostgres = false`. Every hour it writes a consistent point-in-time snapshot using SQLite's `VACUUM INTO` command (safe with WAL mode, no locking or downtime).

Three rolling slots are kept, overwriting the oldest each cycle:

```
$WW_DATA_DIR/backups/witness-watcher.backup.0.db
$WW_DATA_DIR/backups/witness-watcher.backup.1.db
$WW_DATA_DIR/backups/witness-watcher.backup.2.db
```

The `Backup(destPath string) error` method was added to `internal/store/store.go`. The PostgreSQL implementation has a no-op version of the same method — Replit manages PostgreSQL backups at the infrastructure level.

## 4. Replit Workflow & Deployment Config

**Development workflow** (`Start application`):
```
PORT=8080 go run ./cmd/server
```

**Production deployment** (configured in `.replit`):
```
build: go build -o witness-watcher ./cmd/server
run:   PORT=8080 WW_DATA_DIR=/data ./witness-watcher
```

Deployment target is set to **VM** (not autoscale) because the SQLite file and service identity key (`service_identity.json`) must persist on disk between requests. On Replit VM, the `/data` directory is durable across restarts.

---

## 5. DNS & Custom Domains

Both `witness.grapeid.org` and `watcher.grapeid.org` point to the **same** running instance — this service exposes both API surfaces on one binary.

After publishing on Replit, add both custom domains in **Publishing → Custom Domains**, then add CNAME records at your DNS provider:

| Domain | Type | Value |
|--------|------|-------|
| `witness.grapeid.org` | CNAME | `deployment-proxy.replit.com` |
| `watcher.grapeid.org` | CNAME | `deployment-proxy.replit.com` |

TLS is handled automatically by Replit.

---

## 6. Go Dependency Added

```
github.com/lib/pq v1.12.3
```

Added to `go.mod` / `go.sum` to support the PostgreSQL backend. The SQLite build does not use this package at runtime — it is only imported when `UsePostgres = true`.
